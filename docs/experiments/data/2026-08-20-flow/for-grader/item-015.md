# 랜딩 페이지 고유 디자인 만들기

## 개요
이 스킬은 랜딩 페이지를 만들기 전에 그 페이지의 주제에서 직접 디자인 선택을 끌어내고,
AI가 기본값처럼 반복하는 흔한 룩으로 흘러가지 않았는지 코드를 쓰기 전에 미리 검토하는 절차입니다.
목표는 "예쁘다"가 아니라 "이 주제가 아니면 나올 수 없는 화면"입니다.

## 1단계 — 주제를 구체적으로 못박기
디자인을 시작하기 전에 아래 세 가지를 한 문장씩으로 명확히 정합니다. 사용자가 이미 말했으면 그대로 쓰고,
비어 있으면 먼저 사용자에게 확인합니다.

- **구체적 주제 1개**: 예를 들어 "포트폴리오"가 아니라 "3D 프린팅으로 미니어처 만드는 취미 기록"처럼, 실제로 만질 수 있는 소재·업계 용어가 나올 만큼 구체적이어야 합니다.
- **청중**: 이 페이지를 볼 사람이 누구인지.
- **페이지의 단일 목적**: 방문자가 이 페이지를 보고 무엇을 하길 바라는지 하나로.

이 세 가지가 이후 모든 색·폰트·문구 선택의 근거가 됩니다. 여기가 흐리면 뒤로 갈수록 무난한 기본값으로 미끄러집니다.

## 2단계 — 히어로(첫 화면)를 주제의 세계에서 끌어오기
히어로 영역은 이 페이지의 주장입니다. 디자인이 아니라 **주제 고유의 소재·질감·용어**에서 무엇을 보여줄지 고릅니다.

- 카피 자체가 강하게 설 수 있으면 → **헤드라인 문장** 하나로 승부
- 주제의 실물·질감을 바로 보여주는 게 나으면 → **이미지**
- 변화나 과정이 핵심이면 → **애니메이션**
- 직접 만져보는 게 가장 설득력 있으면 → **라이브 데모**
- 참여 자체가 메시지면 → **인터랙티브 요소**

이러지 말 것: 큰 숫자 + 작은 라벨 + 보조 스탯 + 그라데이션 배경 — 이건 어떤 주제에도 붙일 수 있는 템플릿 답이라, 정말 이게 최선일 때만 씁니다.

## 3단계 — 흔한 AI 기본 룩 세 가지를 알고 피하기
아래 세 가지는 특정 브리프에서는 정당할 수 있지만, 아무 지시 없이 놔두면 AI가 저절로 흘러가는 **기본값**입니다.
지금 만들려는 디자인이 이 셋 중 하나로 가고 있지 않은지 스스로 점검합니다.

- 따뜻한 크림 배경(#F4F1EA 근처) + 고대비 세리프 헤드라인 + 테라코타 색 포인트
- 거의 검정에 가까운 배경 + 밝은 형광 그린 또는 선명한 버밀리언 포인트 하나
- 가는 실선 구분선 + 각진 모서리(border-radius 없음) + 신문처럼 빽빽한 다단 레이아웃

예외: 사용자가 이 룩 중 하나를 직접 원한다고 말했다면 그대로 따릅니다. 사용자의 말이 항상 이 규칙보다 우선입니다.

## 4단계 — 대담함은 한 곳에만 집중하기
페이지 전체를 화려하게 만들려 하지 말고, 기억에 남을 요소(시그니처) 하나만 세게 만들고 나머지는 절제합니다.
숫자 마커나 구분선 같은 장식적 구조 요소를 쓸 거라면, 그게 실제로 의미 있는 정보(순서·시점 등)를 담고 있는지 확인합니다. 의미 없이 장식으로만 쓰는 마커는 뺍니다.

## 5단계 — 디자인 토큰 표로 정리하기
코드를 쓰기 전에 아래 표를 채웁니다. 이게 이후 모든 결정의 기준이 됩니다.

| 항목 | 내용 |
|---|---|
| Color | 이름 붙인 hex 코드 4~6개 (예: Deep Navy #1B2A41) |
| Type | 헤드라인용 폰트 / 본문용 폰트 (역할 구분해서) |
| Layout | 한 문장 설명 + 대략적인 구조 스케치 |
| Signature | 이 페이지에서 기억에 남을 단 하나의 요소 |

폰트는 헤드라인에서 개성을 내고 본문은 가독성을 지키는 걸 기본으로 합니다. 실행 환경에서 쓸 수 있는 폰트가 제한적이면, 폰트 이름이 아니라 성격(세리프/산세리프, 굵기 대비)을 기준으로 대체 폰트를 고릅니다.

## 6단계 — 만들기 전에 스스로 검토하기
토큰 표를 다 채운 뒤, 코드를 쓰기 전에 한 번 더 점검합니다.

- 이 색·폰트·레이아웃 조합이 "비슷한 종류의 다른 랜딩 페이지"에도 그대로 붙일 수 있는 조합인가? → 그렇다면 다시 1~2단계로 돌아가 주제에서 더 구체적인 것을 끌어옵니다.
- 3단계에서 나열한 세 가지 흔한 룩 중 하나에 걸리는가? → 걸리면 걸리는 부분만 바꿉니다.
- 시그니처 요소가 정말 하나로 좁혀졌는가, 아니면 화려한 걸 여러 개 욱여넣고 있는가?

문제가 없으면 이제 실제로 만들기 시작합니다.

## 지켜야 할 최소 기준
아래는 따로 자랑하거나 언급하지 않고 조용히 지키는 기본 품질선입니다.

- 모바일 화면까지 반응형으로 동작하는가
- 키보드로 포커스 이동 시 포커스 표시가 눈에 보이는가
- `prefers-reduced-motion` 설정을 존중해 과한 애니메이션을 줄이는가
