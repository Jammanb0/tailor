# 랜딩 페이지 고유 디자인 잡기

## 개요
랜딩 페이지를 만들기 전에 이 스킬을 먼저 거치면, 색·폰트·핵심 요소를 주제에서 직접 끌어내고 흔한 기본값으로 새지 않았는지 스스로 점검한 뒤에 코드를 씁니다. 목표는 "예쁘게"가 아니라 "이 페이지가 이 주제만의 것으로 보이게" 하는 것입니다.

## 주제에서 디자인을 끌어낸다
브리프(요청 내용)가 주제를 정확히 정하지 않았다면 먼저 스스로 고정하세요:
- 구체적인 주제 1개 (예: "생산성 앱"이 아니라 "혼자 작업하는 프리랜서용 인보이스 관리 도구")
- 타깃 독자 1그룹
- 이 페이지의 유일한 목적 (가입 유도? 정보 전달? 데모 신청?)

이 세 가지를 정했다면, 색·폰트·히어로(맨 위 첫 화면) 구성 요소를 전부 이 주제의 세계 안에서 찾으세요. 주제와 관련된 소재·도구·업계 용어·질감에서 나온 선택은 고유해지고, "일반적으로 스타트업 페이지에 쓰이는 것"에서 나온 선택은 뻔해집니다.

히어로에 무엇을 놓을지는 주제 성격에 따라 고르세요:
- 카피(문구) 자체가 강하다 → 헤드라인 문장으로 연다
- 주제의 실물·질감이 중요하다 → 이미지로 연다
- 변화나 과정이 핵심이다 → 애니메이션으로 연다
- 직접 만져보는 게 제일 설득력 있다 → 라이브 데모로 연다

주의: 큰 숫자 + 작은 라벨 + 그라데이션 포인트 컬러 조합은 정말 최선이라고 확신할 때만 쓰세요. 이게 히어로의 "기본 정답"처럼 반사적으로 나온다면 일단 의심하세요.

## AI가 자주 빠지는 세 가지 기본 룩을 피한다
아래 세 가지는 특정 브리프에서는 정당할 수 있지만, 주제와 무관하게 반복적으로 나오는 "생각 없는 기본값"입니다. 만들면서 지금 결과물이 여기로 흘러가고 있지 않은지 확인하세요.

- 따뜻한 크림 배경(#F4F1EA 근처) + 고대비 세리프 디스플레이체 + 테라코타 포인트 컬러
- 거의 검은색 배경 + 밝은 라임그린 또는 버밀리언(주황빛 빨강) 포인트 컬러 하나
- 얇은 실선 구분선 + 각진 모서리(border-radius 없음) + 신문식 다단 레이아웃

예외: 사용자가 브리프에서 이 룩 중 하나를 명시적으로 요구했다면 그대로 따르세요. 사용자의 명시적 지시가 항상 이 규칙보다 우선합니다.

## 디자인 토큰을 코드 쓰기 전에 먼저 정한다
아래 네 가지를 먼저 정하고 승인받은 뒤에 실제로 코드를 쓰세요. 순서를 지키는 이유는, 코드를 먼저 짜면 손에 익은 기본값으로 새기 쉽기 때문입니다.

- **색**: 이름을 붙인 hex 코드 4~6개 (예: Deep Navy #1B2A41, Warm Sand #E8DCC8...) — 배경, 주 강조, 보조 강조, 텍스트 자리에 각각 배치
- **폰트**: 헤더(제목)용과 본문용을 역할로 나눠서 정함. 헤더는 개성을, 본문은 가독성을 우선
- **레이아웃**: 한 문장 설명 + 간단한 텍스트 스케치(ASCII로 대략적인 구획을 그려도 됨)
- **시그니처 요소**: 이 페이지를 기억에 남기는 단 하나의 장치 (번호 매기기, 특정 애니메이션, 독특한 구분선 등 — 단, 장식이 아니라 내용에 관해 실제로 참인 것을 담아야 함. 예를 들어 순서가 없는 항목에 01/02/03을 붙이는 건 장식입니다)

이 계획을 사용자에게 먼저 보여주고, 승인을 받은 뒤에 실제 코드를 작성하세요.

## 대담함은 한 곳에만, 나머지는 절제한다
시그니처 요소 하나에만 힘을 주고 나머지는 조용하게 둡니다. 요소가 여러 곳에서 동시에 튀면 아무것도 기억에 남지 않습니다. 브리프에 실제로 복무하지 않는 장식은 잘라내세요.

모션(애니메이션)을 쓸 거라면 어디에 쓸지, 혹은 아예 안 쓸지를 함께 정하세요:
- 페이지 로드 시퀀스 — 첫인상용, 한 번만 짧게
- 스크롤에 따라 등장 — 읽는 속도에 맞춰 정보를 드러냄
- 호버 시 작은 반응 — 조작 가능함을 알림, 작고 빠르게
- 배경의 은은한 분위기 — 주의를 뺏지 않는 선에서

## 코드 쓰기 전, 계획을 브리프에 비춰 한 번 검토한다
디자인 토큰 계획을 다 세웠으면 바로 코드로 넘어가지 말고, 각 항목이 "비슷한 종류의 페이지라면 아무거나 나올 법한 기본값"으로 읽히는지 스스로 점검하세요. 의심스러운 부분이 있으면 무엇을, 왜 바꿨는지 짧게 적고 고친 뒤 코드를 씁니다.

## 마지막에 조용히 지킬 것
아래는 자랑하지 않고 그냥 지키는 기본 품질입니다:
- 모바일 화면에서도 깨지지 않는지 (반응형)
- 키보드로 이동할 때 어디에 포커스가 있는지 눈에 보이는지
- 사용자가 애니메이션을 줄이도록 설정했다면 그것을 존중하는지

## 예외
브리프가 이미 특정 색이나 스타일을 지정했다면 이 스킬의 "기본값 피하기" 규칙보다 그 지시를 그대로 따르세요.
