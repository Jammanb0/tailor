# 랜딩 페이지 고유 디자인 스킬

## 개요

랜딩 페이지를 만들 때 AI는 몇 가지 정해진 "기본 룩"으로 자꾸 흘러갑니다. 이 스킬은
코드를 쓰기 전에 주제에서 디자인 선택을 끌어내고, 색·폰트·레이아웃을 미리 계획한 뒤,
그 계획이 흔한 기본값으로 흐르지 않았는지 한 번 검토하고 나서야 실제로 만들도록
순서를 강제합니다.

## 단계

### 1단계: 주제를 구체적으로 고정한다

브리프(요청 내용)가 주제를 특정하지 않았다면 먼저 아래 세 가지를 직접 정하고
사용자에게 확인받습니다.

- 구체적 주제 1개 (예: "포트폴리오"가 아니라 "3D 프린팅 취미 작업물을 보여주는 포트폴리오")
- 청중이 누구인지
- 이 페이지의 단일 목적 (예: 방문자가 이메일을 남기게 하는 것 vs 작업물을 훑어보게 하는 것)

이 세 가지가 뒤에 나올 색·폰트·히어로 형식 결정의 근거가 됩니다.

### 2단계: 히어로(첫 화면)를 주제의 세계에서 끌어낸다

히어로는 이 페이지의 주장입니다. 아래 다섯 형식 중 주제와 목적에 가장 잘 맞는 것을
고르세요. 정말 다른 이유가 없다면 "큰 숫자 + 작은 라벨 + 그라데이션 강조색" 조합은
피하세요 — 이건 히어로의 가장 흔한 정답처럼 보이지만 실제로는 어느 주제에나 붙일 수
있는 템플릿 답안이라 고유하지 않습니다.

- **헤드라인**: 카피(문구) 자체가 강할 때 — 문장 하나로 주장한다
- **이미지**: 주제의 실물·질감을 바로 보여줄 때
- **애니메이션**: 변화나 과정이 주제의 핵심일 때
- **라이브 데모**: 직접 만져보는 것이 가장 설득적일 때
- **인터랙티브 순간**: 참여 자체가 메시지일 때

### 3단계: 흔히 몰리는 세 가지 기본 룩을 알고 피한다

아래 셋은 브리프가 명시적으로 요구하면 그대로 써도 되지만, 요구하지 않았는데
저절로 흘러가는 경우가 대부분입니다. 만들면서 이 셋 중 하나로 가고 있지 않은지
스스로 확인하세요.

- 따뜻한 크림 배경(#F4F1EA 근처) + 고대비 세리프 헤드라인 + 테라코타 강조색
- 니어블랙 배경 + 밝은 애시드 그린 또는 버밀리언 강조색 하나
- 헤어라인(가는 선) 괘선 + 모서리를 전혀 안 둥글게(border-radius: 0) + 신문식 조밀한 다단 레이아웃

**예외**: 사용자가 이 중 하나를 콕 집어 요청했다면 그대로 따르세요. 사용자의 말이
항상 이 규칙보다 우선합니다.

### 4단계: 토큰 계획을 개수까지 정해서 세운다

코드를 쓰기 전에 아래 네 가지를 표(또는 목록)로 정리하고 사용자에게 보여준 뒤
진행 여부를 확인받으세요. "느낌 설명"으로 뭉뚱그리지 말고 실제 값으로 적어야 합니다.

- **색(Color)**: 이름 붙은 hex 코드 4~6개 (예: Deep Navy #1B2A41, Warm Sand #E8C39E ...)
- **타입(Type)**: 헤더용 폰트 하나, 본문용 폰트 하나(필요하면 데이터/캡션용 하나 추가).
  - 세리프 헤더: 격식·전통·신뢰를 말할 때
  - 산세리프 헤더: 현대적·기술적 느낌을 말할 때
  - 본문은 가독성을 위해 산세리프를 권장
- **레이아웃(Layout)**: 전체 구조를 한 문장 산문으로 설명 + 대략적인 구획을 텍스트로 그린 와이어프레임
- **시그니처(Signature)**: 이 페이지에서 딱 하나, 기억에 남을 요소 하나만 정한다. 대담함은 여기 한 곳에 몰아넣고 나머지는 절제합니다.

### 5단계: 계획을 브리프에 비춰 검토한다 (코드 쓰기 전)

4단계에서 만든 계획을 다시 읽으면서 스스로 물어보세요: "이 색·폰트·레이아웃이
비슷한 다른 프로젝트에 그대로 갖다 붙여도 위화감이 없는가?" 그렇다는 느낌이 들면
1단계에서 정한 주제의 구체적인 디테일(소재·용어·질감)을 색이나 시그니처 요소에
더 강하게 반영해서 고치세요. 고쳤다면 무엇을, 왜 바꿨는지 한 줄로 남기세요.

이 검토를 통과한 뒤에만 실제 코드를 작성합니다.

### 6단계: 만들면서 지킬 것들

- **모션(애니메이션)**: 쓸지 말지, 쓴다면 어디에 쓸지 정합니다. 페이지 로드 연출은
  한 번만 짧게, 스크롤에 따라 드러나는 효과, 호버(마우스를 올렸을 때) 반응은 작고
  빠르게. 과하게 뿌리면 그 자체로 흔한 AI 느낌을 만듭니다.
- **복잡도는 방향에 맞춘다**: 화려하고 요소가 많은 방향을 골랐으면 정교하게 끝까지
  다듬고, 미니멀한 방향을 골랐으면 여백과 디테일의 정밀함으로 완성도를 냅니다.
  우아함은 요소를 줄이는 게 아니라 고른 방향을 잘 해내는 것입니다.
- **화면에 들어가는 문구도 디자인의 일부**: 버튼 문구는 눌렀을 때 벌어질 일을
  그대로 씁니다(예: "저장하기"가 "제출"보다 명확). 사용자가 아는 말로 쓰고,
  시스템 내부 용어를 그대로 노출하지 않습니다.
- **품질 최소선(눈에 띄지 않게 지킬 것)**: 모바일까지 반응형으로 동작하는지,
  키보드로 이동했을 때 포커스가 눈에 보이는지, 모션을 줄이는 설정(prefers-reduced-motion)을
  존중하는지 조용히 확인합니다. 이건 자랑할 항목이 아니라 당연히 되어 있어야 할 항목입니다.

## 마무리 체크

- 히어로가 5가지 형식 중 하나를 의도적으로 골랐는가, 아니면 기본값으로 흘렀는가?
- 3단계의 세 가지 흔한 룩 중 하나로 가고 있지 않은가? (브리프가 요구한 경우 제외)
- 색 4~6개, 폰트 역할 2개 이상, 시그니처 요소 정확히 1개가 실제 값으로 정해졌는가?
- 5단계 검토에서 "비슷한 다른 프로젝트에도 그대로 쓸 수 있겠다"는 느낌이 남아있지 않은가?
