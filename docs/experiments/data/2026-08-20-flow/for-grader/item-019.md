# 랜딩 페이지 디자인 — 뻔함 탈출 가이드

## 개요

랜딩 페이지를 만들 때마다 결과물이 어디서 본 듯한 모양이 되는 이유는, 디자인
선택을 주제에서 끌어내지 않고 "이런 페이지엔 보통 이렇게 하지"라는 기본값에서
끌어내기 때문입니다. 이 스킬은 코드를 쓰기 전에 색·폰트·레이아웃을 주제 고유의
세계에서 뽑아내는 계획을 먼저 세우고, 그 계획이 정말 고유한지 점검한 다음에야
만들도록 순서를 강제합니다.

## 1단계 — 주제를 못박는다

브리프(요청)가 주제를 특정하지 않았다면 먼저 아래 세 가지를 직접 정하고
사용자에게 확인받습니다. 이미 정해져 있다면 그대로 적어봅니다.

- **구체적 주제 1개** — "생산성 앱"처럼 넓게 두지 말고 "혼자 쓰는 습관 추적 앱"처럼
  좁힙니다.
- **청중** — 이 페이지를 볼 사람이 누구인지.
- **페이지의 단일 목적** — 가입시키기, 다운로드시키기, 문의받기 중 하나로 좁힙니다.

## 2단계 — 흔한 기본값 세 가지를 피한다

AI가 만든 랜딩 페이지는 아래 세 가지 룩(외형) 중 하나로 자꾸 흘러갑니다. 브리프가
이 중 하나를 명시적으로 요구하지 않는 이상, 아래 모양이 나오고 있다면 다시
주제로 돌아갑니다.

- 따뜻한 크림 배경(`#F4F1EA` 근처) + 고대비 세리프 디스플레이 폰트 + 테라코타 색 강조
- 거의 검은 배경 + 밝은 형광 초록 또는 버밀리언(선명한 붉은주황) 색 강조 하나
- 얇은 실선(헤어라인) 괘선 + 각진 모서리(border-radius: 0) + 신문처럼 조밀한 다단 구성

예외: 사용자가 이 중 하나를 원한다고 명확히 말했다면 그대로 따릅니다. 사용자의
말이 항상 이 규칙보다 우선합니다.

## 3단계 — 히어로 섹션은 "주장"이다

랜딩 페이지 맨 위(히어로)는 이 주제만의 세계(소재·도구·결과물·업계에서 쓰는
말)에서 가장 특징적인 것으로 엽니다. 아래 중 이 주제에 가장 잘 맞는 방식을
고릅니다.

- **헤드라인** — 카피(문구) 자체가 강할 때. 주장을 문장으로 던집니다.
- **이미지** — 주제의 실물이나 질감을 바로 보여줄 수 있을 때.
- **애니메이션** — 변화나 과정 자체가 주제의 핵심일 때.
- **라이브 데모** — 직접 만져보는 것이 가장 설득력 있을 때.
- **인터랙티브 순간** — 사용자가 참여하는 행위 자체가 메시지일 때.

주의: "큰 숫자 + 작은 설명 라벨 + 보조 통계 + 그라데이션 배경" 조합은 히어로의
가장 흔한 정답처럼 보이지만 실제로는 템플릿 답안입니다. 정말 이게 최선이라고
판단될 때만 씁니다.

## 4단계 — 대담함은 한 곳에만 집중한다

기억에 남을 시그니처 요소(이 페이지만의 특징 하나)를 딱 하나 정하고, 나머지는
조용하고 절제되게 둡니다. 번호·구분선·라벨 같은 구조 장치는 내용에 대해 실제로
참인 정보를 담아야 하며, 순서가 독자에게 의미를 주지 않는다면 붙이지 않습니다.

- 나쁜 예: 순서와 무관한 항목에 그냥 01 / 02 / 03 번호를 붙이는 것
- 좋은 예: 실제 진행 순서나 시점이 있는 타임라인에만 번호를 씁니다

예외: 모험하지 않는 것도 위험이 될 수 있습니다. 너무 절제해서 무난하고 심심한
페이지가 되지 않았는지도 함께 확인합니다.

## 5단계 — 색·폰트·레이아웃·시그니처를 계획서로 먼저 정한다

코드를 쓰기 전에 아래 네 가지를 정확한 값으로 정합니다. "느낌"으로 남겨두면
결국 다시 기본값으로 흘러갑니다.

- **Color** — 이름을 붙인 색상 코드(hex) 4~6개. (예: Deep Navy `#1B2A41`)
- **Type** — 헤더(디스플레이)용 폰트와 본문용 폰트를 역할을 나눠 정합니다.
  개성은 헤더에서 드러내고, 본문은 읽기 쉬움을 우선합니다.
  - 세리프 헤더: 격식·전통·신뢰를 말할 때
  - 산세리프 헤더: 현대적이고 중립적인 느낌, 기술·명료함을 말할 때
  - 본문은 산세리프를 기본으로 — 긴 글에서도 읽기 쉽습니다
- **Layout** — 전체 구조를 산문 한 문장으로 설명하고, 필요하면 간단한 텍스트
  구조도(와이어프레임)로 배치를 표현합니다.
- **Signature** — 이 페이지가 기억될 단 하나의 요소.

## 6단계 — 계획을 브리프에 비춰 스스로 검토한다 (만들기 전에!)

5단계에서 정한 계획의 각 항목이 "비슷한 페이지라면 아무거나 나올 법한
기본값"으로 읽히는지 점검합니다. 판정은 감이 아니라 실제 확인으로 합니다 —
비슷한 다른 주제로 같은 절차를 밟았을 때도 같은 결과가 나올 것 같다면, 그건
아직 주제에서 나온 선택이 아니라 일반적인 선택입니다. 문제가 있으면 무엇을
왜 바꿨는지 스스로 말한 뒤 계획을 고칩니다. 이 점검을 통과한 뒤에야 실제
코드를 씁니다.

## 지켜야 할 품질 기준 (드러내지 않고 지키기)

아래는 자랑하듯 언급하지 않고 그냥 기본으로 지킵니다.

- 모바일 화면에서도 잘 보이는 반응형 레이아웃
- 키보드로 이동할 때 초점(포커스)이 눈에 보이는 상태
- 사용자가 애니메이션을 줄이도록 설정했으면(`prefers-reduced-motion`) 그 설정을 존중

## 브리프가 항상 우선한다

이 가이드의 모든 규칙은 사용자가 명시적으로 요청한 내용을 이기지 못합니다.
사용자가 특정 색이나 스타일을 원한다고 말했다면, 그 지시를 그대로 따르고
이 가이드는 사용자가 비워둔 부분에서만 적용합니다.
