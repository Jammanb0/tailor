# React 컴포넌트 접근성 점검 및 수정

## 개요
방금 작성하거나 수정한 React 컴포넌트 파일을 열어 키보드 조작, 스크린리더(화면 내용을 음성으로 읽어주는 보조 기술) 지원, 포커스(지금 키보드 조작의 대상이 어디인지 시각적으로 보여주는 테두리/하이라이트) 표시를 점검하고, 작은 수정은 바로 고치되 구조나 디자인을 바꾸는 수정은 먼저 확인받습니다.

## 언제 쓰나
- React 컴포넌트 파일을 새로 만들었거나 수정한 직후
- "이 컴포넌트 접근성 좀 봐줘" 같은 요청을 받았을 때
- 버튼, 입력창, 모달, 드롭다운처럼 사용자가 직접 조작하는 요소를 다룰 때
- 순수하게 데이터만 보여주는 컴포넌트(텍스트, 이미지 설명 없는 단순 레이아웃)에는 점검할 상호작용 요소가 없으므로 적용 범위가 작거나 해당 없음

## 점검 항목과 처리 기준

파일을 읽고 아래 세 가지를 확인합니다. 항목마다 "무엇을 보는지"와 "발견했을 때 할 일"을 같이 적습니다.

### 1. 키보드 조작 가능 여부
- `onClick`이 `<div>`나 `<span>`처럼 원래 클릭 전용이 아닌 태그에 달려 있는데 `tabIndex`나 키보드 이벤트(`onKeyDown` 등)가 없는 경우를 찾습니다.
- 마우스 클릭만으로 동작하고 Tab 키로 포커스가 가지 않거나 Enter/Space로 실행할 수 없는 요소를 찾습니다.

### 2. 스크린리더용 이름
- 아이콘만 있는 버튼(텍스트 없이 아이콘 컴포넌트만 자식으로 둔 `<button>`)에 `aria-label`이 없는 경우를 찾습니다.
- `<img>`에 `alt`가 없거나, 장식용 이미지인데 `alt=""`가 아닌 경우를 찾습니다.
- `<input>`에 연결된 `<label>`이나 `aria-label`이 없는 경우를 찾습니다.

### 3. 포커스 표시
- CSS에서 `outline: none`이나 `outline: 0`을 포커스 상태에 적용하면서 대체 스타일(다른 테두리, 그림자 등)을 주지 않은 경우를 찾습니다. 포커스가 전혀 안 보이게 되는 경우만 문제로 봅니다.

## 수정 범위 — 알아서 고칠 것과 먼저 물어볼 것

**알아서 바로 고치는 것** (속성 추가/수정 수준):
- `aria-label`, `aria-labelledby`, `aria-describedby`, `role` 추가
- `alt` 속성 추가
- `tabIndex`, `onKeyDown` 같은 키보드 핸들러 추가
- 포커스 스타일을 대체 테두리/그림자로 복원

**먼저 물어보는 것** (구조나 디자인이 바뀌는 수준):
- `<div>`를 `<button>` 같은 시맨틱 태그로 바꾸는 것 — 레이아웃이나 스타일이 깨질 수 있음
- 색상 대비를 바꾸기 위해 색 값을 수정하는 것
- 포커스 테두리의 색, 굵기, 크기를 새로 디자인하는 것
- 컴포넌트 트리 구조(부모-자식 관계, 조건부 렌더링 로직)를 바꾸는 것

구조·디자인 변경이 필요하면 코드를 고치지 말고, 어떤 문제 때문에 어떤 변경이 필요한지 설명한 뒤 사용자의 답을 기다립니다.

## 보고 형식

점검 후 다음 형식으로 짧게 보고합니다.

```
[자동 수정]
- 파일:줄 — 무엇을 고쳤고 왜 (예: Button.tsx:12 — 아이콘만 있는 버튼이라 스크린리더가 읽을 이름이 없었음. aria-label="메뉴 열기" 추가)

[확인 필요]
- 파일:줄 — 무엇이 문제이고 어떤 수정이 필요한지, 왜 구조/디자인 변경이 필요한지
```

문제를 하나도 못 찾았으면 "키보드 조작, 스크린리더 레이블, 포커스 표시 모두 문제없습니다"라고 짧게 답합니다.

## 완료 전 확인
- 파일을 실제로 읽었는가 (추측으로 넘어가지 않았는가)
- 키보드 조작 / 스크린리더 이름 / 포커스 표시 세 가지를 모두 점검했는가
- 자동 수정한 항목이 "속성 추가" 범위를 벗어나지 않았는가 (구조·색·크기를 건드리지 않았는가)
- 확인이 필요한 항목에 대해 코드를 먼저 고치지 않고 설명만 전달했는가
- 보고에 "무엇을 왜 고쳤는지"가 각 항목마다 들어 있는가

## 흔한 실수

| 실수 | 왜 문제인가 | 대신 할 일 |
|---|---|---|
| `<div onClick>`을 발견하고도 `tabIndex`만 추가 | Enter/Space로 실행이 안 돼 여전히 키보드로 조작 불가 | 키보드 이벤트 핸들러까지 같이 추가 |
| 장식용 아이콘 이미지에 `alt`를 설명으로 채움 | 스크린리더가 불필요한 내용을 읽게 됨 | 장식용이면 `alt=""`로 비워 스크린리더가 건너뛰게 함 |
| 포커스 안 보인다고 바로 테두리 색을 디자인해서 추가 | 디자인 변경은 확인이 필요한 영역 | 기본 포커스 스타일(`outline`)을 되살리는 선까지만 하고, 색상 디자인은 먼저 물어봄 |
| 모든 이슈를 "확인 필요"로 몰아서 보고 | 작은 수정까지 매번 승인받게 해 번거로움만 늘림 | 속성 추가 수준인지 구조/디자인 변경인지 먼저 구분 |
