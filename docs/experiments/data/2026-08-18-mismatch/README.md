# 2026-08-18 미스매치 시나리오 사전 측정(before) 원자료

코퍼스 구체값 복원 실험의 **0단계** 자료. 어느 카테고리에도 딱 맞지 않는 요청
2종 × 3회를 **코퍼스를 고치기 전에** 받아둔 것이다.

기준선(`../2026-08-18-baseline/`)의 8종은 전부 카테고리에 맞게 만든 시나리오라,
"요청이 어느 카테고리에도 안 맞을 때"를 시험한 적이 없었다. 코퍼스를 바꾼 뒤에
만들면 대조군이 없어 비교가 성립하지 않으므로 먼저 받아둔다. 이 6건을 기준선
24건과 합치면 **10종 × 3회 = 30건**이 before 자료가 된다.

이 폴더의 내용은 이후 수정하지 않는다.

| 파일 | 무엇 |
|---|---|
| `scenarios.json` | 시나리오 2개. 카테고리 칸은 `(none)` — 해당 카테고리가 없다는 뜻 |
| `run.mjs` | 실행기. 기준선 폴더의 것을 **그대로 복사**해 조건을 맞췄다 |
| `for-grader/generated-docs.json` | 채점자에게 보일 것 — 생성된 SKILL.md 6건 + 상황 설명. 모델 자가 보고는 빠져 있다 |
| `answer-key/self-report.json` | **정답지.** 화면에 뜰 출처 표기. 채점 시 채점자에게 주지 않는다 |
| `raw-results.json` | API 응답 전문 + 소요 시간 |

채점은 이 단계에서 하지 않는다. 개선판 측정 후 같은 채점 규칙
(`../2026-08-18-baseline/GRADING-REPORT.md` 9장)으로 before/after를 함께 채점한다.

## 시나리오 선정 기준

목적은 "코퍼스가 못 쓰는 요청"을 찾는 것이 아니라, **내용 패턴이 걸릴 카테고리가
없을 때 모델이 어떻게 행동하는지**(다른 카테고리에서 얼마나 끌어오는지, 골격 선택이
흔들리는지, 결과가 범용적으로 뭉개지는지)를 개선 전 상태로 기록하는 것이다.
골격(절차형·규율형 등)은 자연히 붙되 코퍼스 9개 카테고리(testing, debugging,
planning, code-review, baseline, design, voice, documentation, explanation) 어디에도
내용이 없는 영역으로 골랐다.

- `09-mismatch-office` — 비개발 사무 작업(월별 매출 엑셀 정리). 코퍼스에 해당 내용 없음.
- `10-mismatch-setup` — 개발 관련이지만 카테고리 밖(개발 환경 세팅·온보딩 점검).

어투와 길이(2~3문장, 초심자 말투)는 기준선 8종에 맞췄다.

## 실행 결과 (사실 기록만, 채점 아님)

- **6/6 성공**, 에러 0건. **되물음(`needsMoreInfo`) 0건** — 카테고리에 안 맞는
  요청에서도 과잉 발동하지 않았다.
- 분량 1,604~2,475자. 기준선과 비슷한 범위.
- **골격 선택이 09에서만 3회 모두 갈렸다**: run1 참조형 / run2 절차형 / run3 규율형.
  10은 3회 모두 절차형으로 동일했다. 같은 요청에 골격이 매번 달라지는 것은
  기준선 8종에서 관찰된 적 없는 양상이지만, 3회 표본이므로 정황일 뿐이다.
- 내용 패턴 출처는 6건 모두 `writing-skills`(baseline)와
  `verification-before-completion`(debugging)에 몰렸다. 09의 2건은 `theme-factory`
  (design)까지 끌어왔다.

## 재현

```bash
# dev 서버가 3000 포트에 떠 있어야 한다
node run.mjs 3
```

조건: `claude-sonnet-5`, `thinking` 비활성, `output_config` 없음(API 기본값),
`max_tokens` 8192, 고급 질문 없이 `{ tool: "cli", situation, language: "ko" }`.
코퍼스는 커밋 `d1820b1` 시점 그대로이며 이 측정 중 수정하지 않았다.
