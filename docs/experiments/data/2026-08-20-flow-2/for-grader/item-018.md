# 랜딩 페이지 고유 디자인 만들기

## 개요

이 스킬은 랜딩 페이지를 만들기 전에 "이 페이지만의 색·폰트·시그니처 요소"를 먼저 정하고,
그것이 정말 이 주제에서 나온 것인지 흔한 기본값인지 점검한 다음에야 코드를 쓰게 합니다.
목적은 화려함이 아니라 **주제에서 자연스럽게 나온 고유함**입니다.

## 1단계 — 주제를 못박는다

브리프(요청 내용)에 주제가 뚜렷하지 않으면 코드를 쓰기 전에 먼저 정합니다.

- 구체적인 주제 1개 (예: "빈티지 카메라 수집 커뮤니티" — "취미 커뮤니티"처럼 뭉뚱그리지 않기)
- 이 페이지를 볼 사람은 누구인가
- 페이지 하나가 하는 일 하나 (가입 유도, 제품 소개, 포트폴리오 등)

이 세 가지를 정했다면 사용자에게 확인받고 다음 단계로 넘어갑니다.

## 2단계 — 흔한 기본값 세 가지를 알아둔다

AI가 만든 페이지는 브리프가 정하지 않은 부분에서 아래 세 가지 룩 중 하나로 자꾸 흘러갑니다.
이 셋은 특정 브리프에서는 정당할 수 있지만, 아무 생각 없이 나오면 문제입니다.

- 따뜻한 크림 배경(#F4F1EA 근처) + 대비 강한 세리프 제목 + 테라코타색 포인트
- 거의 검은 배경 + 밝은 연두색이나 버밀리언색 포인트 하나
- 얇은 실선 + 각진 모서리(border-radius 0) + 신문처럼 빽빽한 여러 단 배치

**단, 사용자가 브리프에서 이 셋 중 하나를 직접 요구했다면 그대로 따릅니다.** 사용자의 말이 항상 이 규칙보다 우선합니다.

## 3단계 — 주제의 세계에서 재료를 끌어온다

색과 폰트, 그리고 이 페이지를 대표할 히어로(첫 화면)의 표현 방식을 주제 고유의 세계(소재·도구·산물·그 업계에서 쓰는 말)에서 끌어옵니다. 일반적인 "예쁜 색"이 아니라 "이 주제라서 나온 색"이어야 합니다.

히어로는 이 페이지의 주장입니다. 아래 중 이 주제에 가장 잘 맞는 방식을 고릅니다.

- 헤드라인 — 카피 자체가 강할 때, 문장으로 주장한다
- 이미지 — 주제의 실물·질감을 바로 보여줄 때
- 애니메이션 — 변화나 과정이 주제의 핵심일 때
- 라이브 데모 — 직접 만져보는 것이 가장 설득적일 때
- 인터랙티브 순간 — 참여 자체가 메시지일 때

큰 숫자 + 작은 설명 + 그라데이션 포인트 조합은 히어로의 "정답 템플릿"처럼 쓰이는 흔한 답입니다. 정말 이게 최선일 때만 씁니다.

## 4단계 — 디자인 토큰을 표로 정한다

코드를 쓰기 전에 아래 네 가지를 먼저 정합니다. 여기서 정한 것이 이후 모든 디자인 판단의 기준이 됩니다.

| 항목 | 내용 |
|---|---|
| 색 | 이름 붙인 hex 코드 4~6개 (예: Deep Navy `#1B2A41`) |
| 폰트 | 제목용 / 본문용 최소 2역할 (필요하면 데이터·캡션용 추가) |
| 레이아웃 | 한 문장으로 설명 + 간단한 구조 스케치 |
| 시그니처 요소 | 이 페이지가 기억될 단 하나의 장치 |

**시그니처는 하나만 대담하게, 나머지는 절제합니다.** 번호·구분선·라벨 같은 장치를 쓸 거면 그것이 실제로 뭔가 참인 정보를 담아야 합니다(예: 실제 순서, 실제 시점). 아무 의미 없이 "01 / 02 / 03"을 붙이는 건 장식일 뿐입니다.

폰트는 역할을 나눠서 고릅니다.

- 세리프 제목 — 격식·전통·신뢰를 말할 때
- 산세리프 제목 — 현대적이고 명료함을 말할 때
- 본문은 가독성이 우선이라 산세리프를 기본으로 하고, 개성은 제목 쪽에서 냅니다

## 5단계 — 만들기 전에 스스로 검토한다

토큰 표를 다 채웠으면, 코드를 쓰기 전에 딱 하나만 스스로 물어봅니다.

> "이 계획이, 비슷한 종류의 페이지를 아무 생각 없이 만들 때 나올 법한 결과와 같은가?"

같다고 느껴지면 색이나 시그니처 요소를 주제 쪽으로 더 끌고 가서 고칩니다. 고쳤다면 무엇을, 왜 바꿨는지 한 줄로 남깁니다. 이 점검을 통과한 뒤에만 실제 코드를 씁니다.

## 6단계 — 놓치기 쉬운 기본 품질

아래는 자랑할 필요 없이 그냥 지키는 것들입니다.

- 모바일 화면에서도 깨지지 않는다 (반응형)
- 키보드로 이동할 때 지금 어디 있는지 눈에 보인다 (포커스 표시)
- 모션을 줄이고 싶어하는 사용자 설정을 존중한다 (`prefers-reduced-motion`)

## 지켜야 할 것

- 브리프가 특정 스타일을 요구했다면 무조건 그것을 따른다
- 시그니처 요소는 페이지당 하나로 제한한다 — 여러 개면 아무것도 기억에 안 남는다
- 색은 최소 4개, 최대 6개로 이름까지 붙여 정한다 — "그냥 파란색 계열" 같은 모호한 상태로 코드를 쓰지 않는다
- 3단계(흔한 기본값 세 가지)로 흘러갔는지 5단계에서 반드시 다시 확인한다
