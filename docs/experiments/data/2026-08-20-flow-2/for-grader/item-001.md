# 랜딩 페이지 고유 디자인 만들기

## 개요

랜딩 페이지가 뻔해 보이는 건 대부분 디자인을 "일반적으로 예쁜 것"에서 시작하기 때문입니다.
이 스킬은 반대로, 페이지의 **주제 자체**에서 색·폰트·구성을 끌어내고, 코드를 쓰기 전에
그 결정을 사람이 눈으로 확인하는 절차를 강제합니다. 그래야 "AI가 만든 티가 나는" 몇 가지
기본 룩으로 새는 걸 미리 잡을 수 있습니다.

## 절차

### 1단계 — 주제를 못박기

랜딩 페이지 브리프(요청 내용)가 주제를 분명히 정하지 않았다면, 먼저 아래 세 가지를
구체적으로 정하고 사용자에게 확인합니다. 이 세 가지가 뒤따르는 모든 디자인 결정의 근거가
됩니다.

- **구체적 주제 1개** — "생산성 앱"이 아니라 "혼자 쓰는 작업 로그 도구"처럼 좁게
- **청중** — 누가 이 페이지를 보고 무엇을 하길 바라는가
- **페이지의 단일 목적** — 가입, 다운로드, 문의 등 딱 하나

이미 브리프에 명시돼 있으면 이 단계는 건너뛰고 그대로 사용합니다.

### 2단계 — 흔한 기본값 세 가지를 먼저 알아두기

아래 세 가지는 특정 브리프에서는 정당한 선택일 수 있지만, AI가 별생각 없이 기본값으로
자주 집는 조합입니다. 3단계에서 팔레트·폰트를 정할 때 이쪽으로 흘러가지 않았는지
스스로 확인하는 기준으로 씁니다.

- 따뜻한 크림 배경(`#F4F1EA` 근처) + 대비 강한 세리프 제목 + 테라코타색 강조
- 거의 검은 배경 + 밝은 형광 그린 또는 버밀리언 강조 색 하나
- 가느다란 선(헤어라인) + 모서리 각짐(radius 0) + 신문처럼 촘촘한 다단 구성

예외: 사용자가 브리프에서 이 스타일 중 하나를 직접 요청했다면 그대로 따릅니다.
사용자의 명시적 요청이 이 규칙보다 항상 우선합니다.

### 3단계 — 주제에서 디자인 재료를 끌어내기

주제의 세계(소재, 도구, 전문 용어, 그 분야 사람들이 실제로 보는 것들)에서 색과 폰트를
끌어냅니다. "예쁜 색"이 아니라 "이 주제라면 자연스러운 색"을 찾는 게 목표입니다.

아래 네 가지를 정해서 사용자에게 먼저 보여주고, 승인을 받은 뒤에만 다음 단계로 넘어갑니다.
(이 확인 단계는 절대 건너뛰지 않습니다 — 코드를 쓰기 시작하면 되돌리기 번거롭습니다.)

- **색 팔레트**: hex 코드로 4~6개. 이름 + 실제 값 + 어디에 쓰는지(배경/주 강조/보조 강조/텍스트)를 함께 적습니다.
  예: `Deep Navy #1B2A41` — 배경, `Rust Orange #C4623B` — 버튼 강조
- **폰트 짝**: 제목용과 본문용을 역할을 나눠서. 이름을 못 쓰는 환경이면 "세리프/산세리프, 굵기 대비" 같은 성격으로 대신 적습니다.
- **레이아웃 한 문장 요약**: 이 페이지가 어떤 구조로 흐르는지 한 문장 산문으로.
- **시그니처 요소 1개**: 이 페이지를 기억에 남게 할 단 하나의 장치. (전부를 화려하게 하지 말고 한 곳에만 힘을 준다)

히어로 영역(맨 위 화면)을 열 때는 주제 세계에서 가장 특징적인 것으로 엽니다. 카피가 강하면
헤드라인 문장으로, 실물·질감이 중요하면 이미지로, 과정이 핵심이면 애니메이션으로,
직접 만져보는 게 나으면 라이브 데모로 엽니다. 무작정 "큰 숫자 + 작은 라벨 + 그라데이션"
조합은 최후의 선택으로 남겨둡니다 — 이건 사실상 템플릿 정답이라 고유함이 없습니다.

### 4단계 — 만들기 전에 스스로 비교해보기

3단계에서 정한 계획을 코드로 옮기기 전에, 딱 한 번 스스로 되물어봅니다:

> "생산성 앱", "포트폴리오", "SaaS 랜딩" 같은 비슷한 부류의 다른 프로젝트에 이 계획을
> 그대로 붙여도 어색하지 않을까?

어색하지 않다면 — 즉 이 주제만의 특징이 안 보인다면 — 색이나 시그니처 요소를 다시
주제 쪽으로 당겨서 고칩니다. 고쳤다면 무엇을 왜 바꿨는지 한 줄로 남깁니다.
이 점검은 한 번만 하고 끝냅니다. 계속 의심하면 끝이 없습니다.

### 5단계 — 구현

승인된 팔레트·폰트·레이아웃·시그니처 요소를 기준으로 실제 코드를 작성합니다. 이때도
지켜야 할 최소 기준이 있습니다(따로 자랑하지 않고 그냥 지킵니다):

- 모바일 화면까지 반응형으로 동작한다
- 키보드로 이동할 때 포커스가 눈에 보인다
- `prefers-reduced-motion`(움직임 줄이기 설정)을 존중해 과한 애니메이션을 줄인다

모션(움직임 효과)을 넣을지는 신중하게 정합니다. 페이지 로드 시 한 번 연출하는 정도,
스크롤에 따라 내용이 드러나는 정도, 버튼에 마우스를 올릴 때의 작은 반응 정도면 충분한
경우가 많습니다. 이것저것 다 넣기보다 꼭 필요한 곳에만 씁니다.

## 지켜야 할 것

- 사용자의 명시적 요청(색, 스타일, 폰트 등)이 있으면 그것이 이 스킬의 모든 규칙보다 우선한다.
- 3단계에서 정한 팔레트·폰트·시그니처 요소는 사용자 승인 없이 코드를 먼저 쓰지 않는다.
- 복잡한 디자인을 택했으면 정교하게, 단순한 디자인을 택했으면 여백과 디테일을 정밀하게 — 우아함은 요소 개수가 아니라 실행의 완성도에서 나온다.
