# 랜딩 페이지 디자인 — 흔한 룩 피하기

## 개요

랜딩 페이지를 만들 때 색과 폰트를 대충 고르면 AI가 기본값으로 자주 향하는
세 가지 "뻔한 룩" 중 하나로 흘러갑니다. 이 스킬은 주제에서 디자인을
끌어내고, 코드를 쓰기 전에 계획을 세워 스스로 검토하는 절차를 거쳐
그 흔한 룩을 피하도록 돕습니다.

## 단계

### 1단계 — 주제를 구체적으로 고정한다

브리프(사용자의 요청)가 주제를 애매하게 남겨두면 먼저 아래를 명확히 합니다.
확실하지 않으면 사용자에게 짧게 물어보고 진행합니다.

- 구체적 주제 1개 (예: "생산성 앱" 말고 "혼자 쓰는 습관 트래커")
- 청중이 누구인지
- 이 페이지의 단일 목적 (가입 유도? 포트폴리오 소개? 대기자 명단?)

디자인 선택(색, 폰트, 히어로 구성 방식)은 이 주제의 세계 — 소재, 도구,
그 분야 특유의 용어나 이미지 — 에서 끌어내야 합니다. 일반적인 "스타트업
느낌"이 아니라 이 주제만이 가진 특징에서 시작하세요.

히어로(페이지 맨 위 첫 화면)는 주장입니다. 아래 중 이 주제에 가장
어울리는 방식을 고르세요:

- 헤드라인 — 카피(문구) 자체가 강할 때
- 이미지 — 주제의 실물이나 질감을 바로 보여줄 때
- 애니메이션 — 변화나 과정 자체가 주제의 핵심일 때
- 라이브 데모 — 직접 만져보는 것이 가장 설득력 있을 때

기본값처럼 보이는 조합(큰 숫자 + 작은 라벨 + 그라데이션 강조색)은
정말 이게 최선일 때만 쓰세요.

### 2단계 — 피해야 할 세 가지 기본 룩을 확인한다

아래 세 가지는 특정 상황에는 정당할 수 있지만, 주제와 상관없이 반복돼서
나온다면 문제입니다. 3단계에서 계획을 세우기 전에 이 목록을 다시 읽고
지금 만들려는 것이 여기 걸리는지 점검하세요.

- 따뜻한 크림색 배경(#F4F1EA 근처) + 고대비 세리프 큰 제목 + 테라코타(주황벽돌색) 강조
- 거의 검은 배경 + 밝은 애시드 그린 또는 버밀리언(주홍) 강조색 하나
- 머리카락처럼 얇은 선(헤어라인) + 각진 모서리(border-radius: 0) + 신문 지면처럼 촘촘한 다단 레이아웃

예외: 사용자가 이 룩 중 하나를 명시적으로 요청했다면 그대로 따르세요.
사용자의 말이 항상 이 규칙보다 우선합니다.

### 3단계 — 디자인 토큰 계획을 먼저 세운다 (코드 작성 전)

코드를 쓰기 전에 아래 네 가지를 정확한 값으로 정합니다. "느낌"이나
"분위기"로만 적으면 안 되고, 실제로 쓸 값을 적어야 합니다.

- **색(Color)**: 이름을 붙인 hex 코드 4~6개 (배경 / 주 강조색 / 보조 강조색 / 텍스트 색 등 역할 지정)
- **타이포그래피(Type)**: 제목용 폰트와 본문용 폰트를 역할별로 구분해서 지정
- **레이아웃(Layout)**: 한두 문장으로 구조를 설명 (필요하면 ASCII 와이어프레임으로 간단히 스케치)
- **시그니처(Signature)**: 이 페이지가 기억에 남을 단 하나의 요소 — 나머지는 절제하고 이 요소 하나만 대담하게

예시 형식:
```
Color: Deep Navy #1B2A41 / Rust Orange #C1502E / Warm Sand #E8DCC4 / Charcoal Text #2A2A2A
Type: 제목 — Fraunces (세리프) / 본문 — Inter (산세리프)
Layout: 좌측 텍스트 + 우측 실물 이미지의 2단 히어로, 이후 세로 스크롤 단일 컬럼
Signature: 스크롤에 따라 천천히 회전하는 손으로 그린 듯한 아이콘 하나
```

타이포그래피를 정할 때 참고:
- 세리프 제목 = 격식·전통·신뢰를 말할 때
- 산세리프 제목 = 현대적·기술적·명료함을 말할 때
- 본문은 가독성을 우선해 산세리프를 기본으로 권장
- 실제 실행 환경에서 특정 폰트를 못 쓸 수 있습니다. 그때는 폰트 이름이 아니라
  성격(세리프/산세리프, 굵기 대비가 큰지 작은지)을 맞춰서 대체하세요.

모션(애니메이션)을 쓸 거라면 어디에 쓸지와 아예 안 쓸지를 함께 정하세요.
페이지 로드 시 한 번 나오는 짧은 시퀀스, 스크롤에 반응하는 등장 효과,
호버 시 작은 반응 중 이 페이지에 맞는 것만 고르고 나머지는 넣지 않습니다.

### 4단계 — 계획을 브리프에 비춰 검토한다 (코드 작성 전, 두 번째 패스)

3단계에서 세운 계획을 다시 읽으면서 각 부분에 대해 자문하세요:

> "이게 '이런 종류의 페이지'라면 아무 프롬프트에나 나올 법한 기본값처럼
> 보이는가, 아니면 이 특정 주제에서만 나올 수 있는 선택인가?"

2단계의 세 가지 기본 룩과 비교해서 겹치는 부분이 있다면 그 부분만
바꾸고, 무엇을 왜 바꿨는지 한 줄로 남기세요. 이 검토를 통과한 뒤에야
실제 코드를 작성합니다.

### 5단계 — 만들면서 지킬 것

- 대담함은 시그니처 요소 한 곳에 집중하고 나머지는 조용하게 둡니다.
  숫자 라벨이나 구분선 같은 장치를 쓴다면 그것이 실제로 의미 있는
  정보(진짜 순서, 진짜 시점)를 담고 있어야 합니다. 순서가 아닌데
  번호를 붙이는 것은 장식이니 피하세요.
- 복잡도는 고른 방향에 맞춥니다. 화려하고 요소가 많은 방향을 골랐으면
  정교하게 마무리하고, 미니멀한 방향을 골랐으면 여백과 디테일의
  정밀함으로 우아함을 만드세요. 요소를 줄이는 것 자체가 우아함은
  아닙니다.
- 화면의 문구(카피)도 디자인 재료로 다룹니다. 사용자가 실제로 이해하는
  말로 쓰고("변경사항 저장" 등 눌렀을 때 벌어질 일을 그대로), 시스템
  구현 방식을 그대로 노출하는 용어는 피합니다. 에러 문구는 사과 대신
  무엇이 잘못됐고 어떻게 고치는지를 말합니다.
- 아래는 눈에 띄게 자랑하지 않아도 항상 지키는 기본선입니다:
  - 모바일 화면까지 반응형으로 동작하는지
  - 키보드로 포커스를 옮겼을 때 어디에 있는지 눈에 보이는지
  - 사용자가 모션을 줄이도록 설정했을 때(prefers-reduced-motion) 이를 존중하는지

## 마무리

계획(3단계) → 검토(4단계) → 구현(5단계)까지 마쳤다면, 마지막으로 2단계의
세 가지 기본 룩 목록을 다시 한번 열어 결과물과 대조하세요. 겹치는 부분이
없다면 완료입니다. 겹친다면 그 부분만 구체적으로 어떻게 다르게 바꿀지
정해서 반영하세요.
