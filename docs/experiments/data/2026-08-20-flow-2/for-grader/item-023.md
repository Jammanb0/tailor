# 랜딩페이지 고유 디자인 만들기

## 개요

랜딩 페이지 디자인이 뻔해지는 이유는 대개 순서 때문입니다 — 색과 폰트를 정하지 않은 채 코드부터 쓰면, 손이 익숙한 기본값(요즘 AI 도구들이 즐겨 쓰는 크림색 배경+세리프체, 혹은 다크 배경+네온 그린 같은 조합)으로 자연스럽게 흘러갑니다. 이 스킬은 코드를 쓰기 전에 **주제에서 색·폰트·시그니처 요소를 먼저 끌어내고**, 완성된 계획을 "혹시 흔한 기본값은 아닌지" 검토한 뒤에야 실제로 만들도록 순서를 강제합니다.

## 언제 적용하나

- 새 랜딩 페이지를 처음부터 디자인할 때 — 항상 적용
- 이미 있는 랜딩 페이지가 뻔해 보여서 다시 디자인할 때 — 항상 적용
- 사용자가 이미 색상·폰트·스타일을 구체적으로 지정한 경우 — 이 스킬을 적용하지 않고 그 지시를 그대로 따릅니다. 사용자의 명시적 지정이 항상 우선합니다.

## 절차

### 1단계 — 주제를 구체적으로 고정한다

브리프(요청 내용)가 막연하면 먼저 아래 세 가지를 직접 정하고, 사용자에게 확인받습니다.

- 이 페이지가 다루는 구체적인 주제 하나 (예: "개인 프로젝트" 대신 "홈베이킹 레시피 아카이브")
- 이 페이지를 볼 사람 (청중)
- 이 페이지 하나가 하려는 단 하나의 목적

**게이트**: 이 세 가지가 정해지지 않으면 다음 단계로 넘어가지 않습니다.

### 2단계 — 주제의 세계에서 소재를 뽑는다

일반적인 "웹디자인 트렌드"가 아니라, 그 주제 고유의 세계(소재·도구·산물·업계 용어·색깔)에서 디자인 선택의 근거를 찾습니다.

- 이 주제를 만졌을 때 손에 잡히는 것은 무엇인가?
- 이 업계·분야에서만 쓰는 색이나 질감이 있는가?
- 이 주제를 가장 잘 아는 사람이 한눈에 알아볼 만한 디테일은 무엇인가?

이렇게 뽑은 소재가 색·폰트·히어로(페이지 맨 위 첫 화면) 선택의 근거가 됩니다.

### 3단계 — 디자인 토큰 4종을 개수를 정해 계획한다

코드를 쓰기 전에 아래 네 가지를 표 형태로 확정합니다. 여기서 "토큰"이란 나중에 코드 전체에서 반복해 쓸 디자인 값(색상 코드, 폰트 이름 등)을 뜻합니다.

| 항목 | 무엇을 정하나 |
|---|---|
| 색 (Color) | 이름 붙인 hex 코드 4~6개. 예: `Deep Navy #1B2A41` |
| 폰트 (Type) | 제목용(디스플레이)과 본문용, 최소 두 역할로 구분 |
| 레이아웃 (Layout) | 전체 구조를 한 문장 산문으로 설명 + 간단한 ASCII 와이어프레임(글자로 그린 레이아웃 스케치) |
| 시그니처 요소 (Signature) | 이 페이지 하면 떠오를 단 하나의 특징적인 요소 |

- 색은 정확히 4~6개로 제한합니다. 배경, 주 강조색, 보조 강조색, 텍스트 색 등 역할까지 함께 적습니다.
- 폰트는 "무슨 폰트가 예쁜가"가 아니라 "이 폰트가 이 주제에 어떤 느낌을 주는가"로 고릅니다.
- 시그니처 요소는 딱 하나만 정합니다. 여러 개를 화려하게 넣기보다, 하나를 확실히 기억에 남게 하고 나머지는 절제합니다.

### 4단계 — 흔한 기본값에 걸리지 않았는지 검토한다 (코드 작성 전 필수)

3단계에서 만든 계획을 아래 흔한 패턴과 대조합니다. 겹치면 코드를 쓰기 전에 이 자리에서 다시 다듬습니다.

**아래 세 가지는 특정 브리프에서는 정당한 선택일 수 있지만, 아무 생각 없이 나오면 뻔한 기본값입니다.**

- 따뜻한 크림 배경(`#F4F1EA` 근처) + 대비 강한 세리프 제목 + 테라코타 계열 강조색
- 짙은 검정에 가까운 배경 + 밝은 형광 그린이나 버밀리언 색 강조 하나
- 얇은 실선 구분선 + 각진 모서리(둥글림 없음) + 신문처럼 빽빽한 다단 레이아웃

**예외**: 사용자가 이 셋 중 하나를 명시적으로 요청했다면 그대로 따릅니다. 사용자의 지시가 항상 이 검토보다 우선합니다.

검토 방법: "이 계획이 다른 비슷한 페이지에도 그대로 쓰일 수 있는가?"를 스스로 물어봅니다. 그렇다는 답이 나오면 1~2단계로 돌아가 주제 고유의 디테일을 다시 찾습니다. 고쳤다면 무엇을 왜 바꿨는지 한 줄로 남깁니다.

### 5단계 — 계획을 보여주고 승인받은 뒤 만든다

3~4단계 결과를 사용자에게 표로 보여주고, "이대로 진행할까요?"라고 묻습니다. 승인 전에는 실제 코드를 작성하지 않습니다.

승인을 받으면 아래 원칙을 지키며 실제 페이지를 만듭니다.

- 대담함은 시그니처 요소 하나에 집중하고, 나머지는 절제된 톤을 유지합니다.
- 애니메이션이나 모션 효과를 쓸 때는 "쓸 곳"과 "쓸지 여부"를 함께 정합니다. 흩뿌리듯 여러 곳에 넣기보다, 첫인상을 만드는 한 순간에 집중하는 편이 대개 더 효과적입니다.
- 화면의 문구(버튼 이름, 안내 문구 등)도 디자인 재료입니다. "제출"보다 "저장하기"처럼 실제로 어떤 일이 일어나는지 그대로 드러나는 말을 씁니다.

### 6단계 — 품질 기준을 티내지 않고 지킨다

아래 세 가지는 "이런 것도 신경 썼다"고 자랑하듯 드러내지 않고, 조용히 기본으로 지킵니다.

- 모바일 화면까지 자연스럽게 반응형으로 보이는가
- 키보드로 이동할 때 지금 어디에 포커스가 있는지 눈에 보이는가
- 사용자가 시스템에서 "동작 줄이기"를 설정했다면 애니메이션을 존중하는가

## 완료 전 점검

- [ ] 주제·청중·목적 세 가지를 구체적으로 정했는가
- [ ] 색 4~6개, 폰트 두 역할 이상, 레이아웃 설명, 시그니처 요소 1개를 모두 확정했는가
- [ ] 4단계의 흔한 기본값 세 가지와 대조해 걸리는 부분이 없는지 확인했는가 (혹은 사용자가 그 스타일을 명시적으로 요청했는가)
- [ ] 계획을 사용자에게 보여주고 승인을 받은 뒤에 코드를 작성했는가
- [ ] 시그니처 요소 하나에 집중하고 나머지는 절제했는가
- [ ] 모바일 반응형·키보드 포커스·모션 감소 설정을 조용히 지켰는가
