# 랜딩 페이지 고유 디자인

## 개요

AI에게 랜딩 페이지를 만들라고 하면 특정 색·폰트·레이아웃 조합으로 자꾸 흘러가는 경향이 있습니다. 이 스킬은 코드를 쓰기 전에 "이 페이지의 주제가 뭔가"부터 정하고, 거기서 디자인 결정을 끌어내며, 몰리기 쉬운 뻔한 조합을 미리 피하는 절차입니다.

## 1단계 — 주제와 목적을 먼저 못박기

디자인 결정은 페이지의 주제(무엇을 다루는 페이지인지, 예: 커피 로스팅, 개인 포트폴리오, 오픈소스 도구 소개) 자체에서 나와야 합니다. 사용자가 이걸 명확히 안 줬다면 임의로 정하지 말고 먼저 확인합니다.

- 이 페이지는 구체적으로 무엇에 관한 건가요? (한 문장으로)
- 보는 사람은 누구인가요?
- 이 페이지 하나로 사람들이 뭘 하길 바라나요? (가입, 문의, 구경, 다운로드 등 — 목적 하나만)

이 답을 받으면, 첫 화면(히어로 영역)을 다음 중 어떤 방식으로 열지 결정하고 그 이유를 사용자에게 한 줄로 밝힙니다:

- **문장형**: 카피 자체가 강할 때 — 주장을 헤드라인으로 던진다
- **이미지형**: 주제의 실물·질감을 바로 보여줄 수 있을 때
- **움직임형**: 변화나 과정 자체가 주제의 핵심일 때
- **직접 체험형**: 데모나 인터랙션을 바로 만져보게 하는 것이 가장 설득력 있을 때

주의: "큰 숫자 + 작은 설명 + 그라데이션 강조" 조합은 정말 그게 최선일 때만 쓰고, 기본값으로 습관적으로 쓰지 않습니다.

## 2단계 — 흔히 몰리는 세 가지 기본 룩 피하기

아래 세 조합은 특정 주제에는 실제로 맞을 수도 있지만, 습관적인 기본값으로 반복해서 나오는 패턴입니다. 사용자가 명시적으로 요청한 게 아니라면 이 조합으로 흘러가지 않는지 만드는 중간에 스스로 확인합니다.

- 따뜻한 크림색 배경 + 대비 강한 세리프(장식이 있는 서체) 제목 + 테라코타(적갈색) 강조색
- 거의 검은 배경 + 형광 초록이나 강렬한 주황 계열 강조색 하나
- 얇은 실선 구분선 + 각진 모서리(border-radius 0) + 신문 같은 촘촘한 다단 배치

예외: 사용자가 이 중 하나를 그대로 원한다고 명시하면 그 지시가 항상 우선합니다.

## 3단계 — 대담함은 한 곳에만 집중하기

페이지 전체를 화려하게 꾸미지 않습니다. 기억에 남을 요소(시그니처 요소) 하나만 정하고, 나머지는 조용하고 절제된 상태로 둡니다. 숫자 마커(01, 02, 03 같은 표시)나 구분선 같은 장치를 쓸 때는 실제로 순서나 시점 정보를 담고 있을 때만 씁니다 — 내용과 상관없이 장식으로만 붙이지 않습니다.

절제가 무난함으로 흐르지 않도록, 시그니처 요소 하나는 확실히 눈에 띄게 만듭니다.

## 4단계 — 디자인 토큰 계획 세우기 (코드 작성 전)

실제 코드를 쓰기 전에 아래 네 가지를 먼저 정리해서 사용자에게 보여줍니다.

- **색**: 이름을 붙인 hex 코드 4~6개 (예: Deep Navy #1B2A41, 배경/주 강조/보조 강조/텍스트용으로 역할 배정)
- **타이포그래피**: 제목용 폰트와 본문용 폰트를 역할을 나눠 정한다. 제목에서 개성을 내고 본문은 가독성을 지킨다.
  - 세리프 제목: 격식·전통·신뢰를 말할 때
  - 산세리프 제목: 현대적·기술적 느낌을 말할 때
  - 본문은 웬만하면 산세리프(긴 글도 읽기 편함)
- **레이아웃**: 산문으로 한 문장 설명 + 대략적인 구조를 텍스트로 그려본 것(ASCII 와이어프레임)
- **시그니처 요소**: 이 페이지에서 기억에 남을 단 하나를 정확히 짚기

## 5단계 — 계획을 스스로 검토한 뒤에야 코드 작성

계획을 다 세운 뒤, 코드를 쓰기 전에 스스로 물어봅니다: "이 계획, 비슷한 주제의 다른 페이지를 만들 때도 똑같이 나올 법한 뻔한 답인가?" 그렇다는 느낌이 들면 어느 부분을 왜 바꿨는지 명확히 하고 다시 잡습니다. 이 자체 검토를 통과한 뒤에야 실제 코드를 작성합니다.

## 6단계 — 조용히 지키는 기본 품질

아래는 자랑하듯 언급할 게 아니라 그냥 당연히 지키는 것들입니다.

- 모바일 화면에서도 깨지지 않는 반응형 레이아웃
- 키보드로 이동할 때 지금 어디에 포커스가 있는지 눈에 보임
- 사용자가 움직임을 줄이도록 설정했으면(prefers-reduced-motion) 애니메이션을 존중

## 지켜야 할 것

- 사용자가 브리프에서 이미 방향을 정해준 부분(색, 스타일, 특정 룩)은 그대로 따른다 — 이 스킬의 "고유하게 만들라"는 원칙보다 사용자의 명시적 지시가 항상 우선한다.
- 주제를 확인하지 않은 채 디자인을 임의로 시작하지 않는다.
- 2단계의 세 가지 기본 룩으로 흘러가지 않았는지 스스로 점검한다.
- 계획(4단계) 없이 곧바로 코드를 쓰지 않는다.
