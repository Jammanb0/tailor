# 랜딩 페이지 고유 디자인 스킬

## 개요

랜딩 페이지를 만들 때 가장 쉬운 길은 어디서 본 듯한 기본값으로 흘러가는 것입니다.
이 스킬은 코드를 쓰기 **전에** 주제에서 디자인 선택을 끌어내고, 흔한 기본 룩을 의식적으로
피하고, 계획을 스스로 비평한 뒤에야 만들도록 순서를 잡아줍니다.

## 단계

### 1단계 — 주제를 고정한다

랜딩 페이지가 무엇에 관한 것인지 먼저 명확히 합니다. 다음 세 가지가 이미 정해져 있지
않다면 사용자에게 묻습니다:

- 구체적인 주제 1개 (예: "생산성 앱" 말고 "회의 시간을 줄여주는 캘린더 도구")
- 청중이 누구인지
- 이 페이지 하나의 단일 목적 (가입 유도인지, 소개인지, 구매 유도인지)

이 답이 이후 모든 색·폰트·문구 선택의 근거가 됩니다.

### 2단계 — 흔한 기본 룩 세 가지를 의식한다

아래 세 가지는 어떤 프로젝트에는 정당한 선택이지만, AI가 아무 생각 없이 기본값으로
집는 패턴이기도 합니다. 지금 만들려는 디자인이 이 중 하나로 흘러가고 있다면 멈추고
이유를 점검하세요.

- 따뜻한 크림 배경 + 고대비 세리프 제목 + 테라코타(주황빛 갈색) 강조색
- 거의 검정에 가까운 배경 + 밝은 형광 그린 또는 버밀리언(선명한 붉은 주황) 강조색 하나
- 얇은 실선(헤어라인) + 각진 모서리(border-radius: 0) + 신문처럼 촘촘한 다단 구성

이 세 가지를 쓰지 말라는 규칙이 아니라, **주제와 무관하게 반사적으로 골랐는지** 스스로
확인하라는 신호입니다. 사용자가 명시적으로 이 룩 중 하나를 요청했다면 그대로 따르세요.

### 3단계 — 디자인 토큰 4종을 먼저 정한다

코드를 쓰기 전에 아래 네 가지를 표 형태로 정리하고, 이후 모든 결정을 여기서 파생시킵니다.

- **색상**: 이름 붙인 hex 코드 4~6개 (예: Deep Navy #1B2A41). 주제의 세계(소재·업계·분위기)에서
  끌어온 색이어야 합니다. 아무 프로젝트에나 쓰는 색이 아니라 "왜 이 색인지"를 한 줄로 답할 수
  있어야 합니다.
- **타이포그래피**: 제목용 폰트와 본문용 폰트를 역할을 나눠 정합니다. 제목에서 개성을 내고
  본문은 가독성을 지킵니다. (실행 환경에 특정 폰트가 없다면 이름 대신 성격 — 세리프/산세리프,
  굵기 대비 — 을 맞추세요.)
- **레이아웃**: 한두 문장으로 구조를 설명하고, 필요하면 텍스트로 간단한 배치 스케치를 그립니다.
- **시그니처 요소**: 이 페이지를 기억에 남게 할 단 하나의 대담한 요소. 나머지는 절제합니다 —
  대담함이 여러 곳에 흩어지면 하나도 기억에 남지 않습니다.

### 4단계 — 히어로(첫 화면)는 주제에서 나온 주장으로 연다

첫 화면은 이 페이지의 주장입니다. 주제의 세계에서 가장 특징적인 것으로 열되, 아래 중
무엇이 가장 설득적인지 판단해 고릅니다.

- 헤드라인(문장으로 된 주장) — 카피 자체가 강할 때
- 이미지 — 주제의 실물·질감을 바로 보여줄 때
- 애니메이션 — 변화나 과정이 핵심일 때
- 라이브 데모 — 직접 만져보는 것이 가장 설득력 있을 때

"큰 숫자 + 작은 설명 + 그라데이션 강조색" 조합은 흔한 정답처럼 보이지만, 정말 최선이라고
판단될 때만 쓰세요.

### 5단계 — 계획을 만들기 전에 스스로 비평한다

3~4단계에서 정한 계획을 다시 읽고 다음을 자문합니다:

- 이 색·폰트·구조가 "비슷한 종류의 페이지라면 아무거나 나올 법한" 것으로 보이는가?
- 이 선택이 1단계에서 정한 주제와 실제로 연결되는가, 아니면 그냥 무난해서 골랐는가?

의심스러우면 무엇을 왜 바꿨는지 한 줄로 남기고 계획을 고칩니다. 이 점검을 통과한 뒤에야
실제 코드를 작성합니다.

### 6단계 — 만들면서 지키는 것

- 복잡도는 택한 방향에 맞춥니다. 화려한 방향이면 정교하게 실행하고, 미니멀한 방향이면
  여백과 디테일의 정밀함으로 우아함을 냅니다. 요소를 줄이는 것 자체가 우아함은 아닙니다.
- 화면의 글(버튼 문구, 안내 문구 등)도 디자인 재료로 다룹니다. "Submit" 대신 눌렀을 때
  벌어질 일을 그대로 쓰세요 (예: "Save changes").
- 모바일 반응형, 키보드로 포커스 이동이 눈에 보이는지, 모션 최소화 설정을 존중하는지는
  기본으로 지키되 티내지 않습니다.

## 마무리

완성된 랜딩 페이지를 사용자에게 보여줄 때는 3단계에서 정한 디자인 토큰 표를 함께
제시하고, 2단계의 흔한 기본 룩과 어떻게 달라졌는지 한두 문장으로 설명하세요.
