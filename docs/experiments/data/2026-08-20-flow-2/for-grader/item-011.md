# 랜딩 페이지 비주얼 아이덴티티 잡기

## 개요

이 스킬은 랜딩 페이지를 만들기 전에 그 페이지만의 색·폰트·스타일을 주제에서 직접 끌어내고, AI가 만든 티가 나는 흔한 기본값으로 흘러가지 않도록 미리 점검하는 절차입니다.

## 왜 결과물이 비슷해지는가

AI에게 "멋진 랜딩 페이지"를 맡기면 주제와 상관없이 자꾸 같은 스타일로 수렴하는 경향이 있습니다. 대표적으로 이 세 가지입니다.

- 따뜻한 크림색 배경(`#F4F1EA` 근처) + 대비 강한 세리프(serif, 삐침이 있는 명조 계열) 제목 + 테라코타(붉은 갈색) 포인트
- 거의 검정에 가까운 배경 + 밝은 형광 그린이나 버밀리언(주황빛 빨강) 포인트 색 하나
- 얇은 실선 구분선 + 각진 모서리(border-radius: 0) + 신문처럼 빽빽한 다단 레이아웃

이 세 가지 자체가 나쁜 건 아니지만, 문제는 **주제와 상관없이 반사적으로 나온다**는 점입니다. 이 스킬은 이 세 가지를 기본값으로 쓰지 않도록 잡아주는 역할을 합니다. 다만 이 문서가 요구하는 다른 것보다, 사용자가 특정 스타일을 콕 집어 요청하면 그 요청이 항상 우선합니다.

## 절차

### 1단계 — 주제를 구체화한다

먼저 아래 세 가지를 명확히 합니다. 사용자가 이미 말했다면 그대로 쓰고, 안 정해졌다면 물어봅니다.

- 이 랜딩 페이지가 다루는 구체적인 주제 (예: "생산성 앱"이 아니라 "혼자 일하는 프리랜서를 위한 인보이스 자동화 도구")
- 이 페이지를 볼 사람 (청중)
- 이 페이지 하나가 하려는 단 하나의 목적 (가입 유도인지, 소개인지, 대기자 명단 모집인지)

이게 애매하면 뒤 단계에서 무엇을 골라도 근거가 없어서, 결국 다시 흔한 기본값으로 돌아가게 됩니다.

### 2단계 — 주제의 세계에서 재료를 끌어온다

일반적인 "세련된 느낌"이 아니라, **그 주제 고유의 세계**(소재, 도구, 결과물, 그 업계에서만 쓰는 표현)에서 색과 이미지 소재를 찾습니다.

예를 들어 원두 로스팅 서비스라면 일반적인 브라운·크림 팔레트 대신, 실제 로스팅 단계별 원두 색(연한 갈색 → 짙은 갈색)에서 팔레트를 뽑는 식입니다. 페이지 맨 위(히어로 영역)는 이 페이지의 핵심 주장을 보여주는 자리이므로, 그 주제 세계에서 가장 특징적인 요소로 엽니다. 아래 중 이 페이지에 가장 잘 맞는 방식을 고릅니다.

- 카피 자체가 강하다 → 헤드라인 문장으로 시작
- 실물·질감을 보여주는 게 설득력 있다 → 이미지로 시작
- 변화나 과정이 핵심이다 → 애니메이션으로 시작
- 직접 만져보는 게 가장 강력하다 → 라이브 데모로 시작
- 참여 자체가 메시지다 → 인터랙티브 요소로 시작

"큰 숫자 + 작은 설명 + 그라데이션 포인트" 조합은 히어로 영역에서 가장 흔하게 나오는 정답 같은 답입니다. 이게 정말 최선일 때만 쓰고, 아니면 다른 방식을 고릅니다.

### 3단계 — 색·폰트·시그니처 요소를 표로 확정한다

아래 형식으로 딱 정해서 문서로 남깁니다. 이후 만드는 모든 요소는 여기서 파생시킵니다.

```
색상: [이름1] #hex1 (배경) / [이름2] #hex2 (주 강조) / [이름3] #hex3 (보조 강조) / [이름4] #hex4 (텍스트)
폰트: 제목용 [폰트명 또는 성격] / 본문용 [폰트명 또는 성격]
레이아웃: (한 문장으로 - 예: "왼쪽 정렬 텍스트 + 오른쪽 실제 화면 스크린샷, 넓은 여백")
시그니처 요소: (이 페이지를 기억에 남게 할 단 하나 - 예: "스크롤하면 원두가 점점 진해지는 애니메이션")
```

- 색은 정확히 4~6개로 이름과 hex 값을 함께 정합니다. "느낌이 좋은 색"이 아니라 실제 코드에 바로 쓸 값이어야 합니다.
- 폰트는 최소 제목용/본문용 두 역할로 나눕니다. 개성은 제목 폰트에서 내고, 본문 폰트는 읽기 편한 것을 우선합니다.
- 시그니처 요소는 딱 하나만 정합니다. 대담한 시도는 한 곳에 집중하고, 나머지는 절제된 상태로 둡니다. 화려한 요소를 여러 개 넣으면 오히려 아무것도 기억에 안 남습니다.
- 순서 정보가 없는데 01 / 02 / 03 같은 숫자 마커를 장식으로 붙이지 않습니다. 실제로 순서나 단계를 의미할 때만 씁니다.

### 4단계 — 만들기 전에 스스로 검토한다

3단계에서 정한 표를 보고, 코드를 쓰기 전에 아래 질문에 답합니다.

- 이 색·폰트·레이아웃 조합이 **다른 주제의 페이지에도 그대로 써도 어색하지 않을** 조합인가요? 그렇다면 주제에서 나온 게 아니라 일반적인 기본값에 가깝다는 뜻입니다.
- 2단계에서 나열한 세 가지 흔한 스타일(크림+세리프+테라코타 / 다크+형광 포인트 / 실선+각진 모서리+신문 레이아웃) 중 하나에 해당하나요? 사용자가 이 스타일을 콕 집어 요청한 게 아니라면 다시 3단계로 돌아가 조정합니다.
- 시그니처 요소가 정말 하나뿐인가요, 아니면 화려한 효과가 여러 개 흩어져 있나요?

여기서 걸리는 게 있으면 3단계로 돌아가 고치고, 왜 무엇을 바꿨는지 한 줄로 남깁니다. 통과하면 그제서야 실제 코드/디자인 작업을 시작합니다.

### 5단계 — 만든 뒤 최소한의 기본기를 확인한다

이건 자랑할 항목이 아니라 그냥 당연히 지켜야 하는 바닥선입니다.

- 모바일 화면 크기에서도 깨지지 않는가
- 키보드로 이동했을 때 지금 어디에 포커스가 있는지 눈에 보이는가
- 사용자가 애니메이션을 줄이도록 설정해뒀다면(`prefers-reduced-motion`) 그걸 존중하는가

## 예외

사용자가 "이런 느낌으로 해줘"라며 특정 스타일(다크 모드, 미니멀, 특정 색 등)을 직접 지정하면 그 지시가 이 스킬의 모든 규칙보다 우선합니다. 이 스킬은 방향이 정해지지 않았을 때 흔한 기본값으로 빠지지 않도록 잡아주는 용도입니다.
