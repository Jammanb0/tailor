# Tailor

자기만의 Claude Code Skill(`.claude/skills/이름/SKILL.md`)을 AI의 도움으로
만드는 웹 서비스.

한국어 | [English](README.en.md)

Claude Code가 처음인 사람이 막히지 않도록 배려하되, **초심자 전용 제품은
아니다.** 쉽게 만든다는 이유로 기술 용어나 구체적인 값을 빼지 않고, 대신 처음
나오는 용어에 짧은 풀이를 붙이는 방향으로 간다.

## 무엇을 하나

| 기능 | 경로 | 설명 |
|---|---|---|
| 용어 사전 | `/glossary` | "스킬", "에이전트", "CLI" 같은 개념 21개를 쉬운 비유로 설명. AI 호출 없음 |
| **스킬 생성기** | `/create` | 몇 가지 질문에 답하면 SKILL.md 초안을 만들어 준다. 핵심 기능 |
| 갤러리 | `/gallery` | 참고할 만한 스킬을 둘러보고 받아 간다 |

## 스킬 생성기의 두 갈래

`/create`에 들어가면 만드는 방법을 고르게 된다.

**이 사이트에서 바로 만들기** — 질문에 답하면 서버가 Claude API를 한 번 호출해
초안을 만든다. 아래 「참고 코퍼스」가 프롬프트에 함께 들어가고, 모델이 실제로
쓴 패턴의 출처가 결과 화면에 표시된다.

**내 Claude로 이어서 만들기** — `claude://` 딥링크로 사용자 본인의 Claude
세션을 열고, 그 안에서 질문·생성·저장까지 진행한다. 실제 프로젝트 파일을
보면서 물어볼 수 있고 비용도 본인 계정으로 나가지만, **참고 코퍼스와 문서
골격은 링크 하나에 담기지 않아 함께 넘기지 못한다.** 결과에 출처 표기도 붙지
않는다. 문서의 짜임새만 놓고 보면 웹 경로가 대체로 낫고, 이 차이는 화면에도
적어 두었다.

이관 경로로 넘기는 프롬프트에는 **"초안을 보여주고 승인받은 뒤에, 저장 위치를
물어보고, 저장 직전 다시 확인받고 나서만 저장하라"** 는 지시가 들어 있다. 다만
이건 코드가 아니라 지시문이므로 100% 강제되지는 않는다.

## 직접 돌려보기

```bash
pnpm install
pnpm dev
```

`http://localhost:3000`에서 열린다.

**생성 기능을 쓰려면 Claude API 키가 필요하다.** 저장소 루트에 `.env.local`을
만들고 키를 넣으면 된다(`.env.example` 참고):

```bash
# .env.local
ANTHROPIC_API_KEY=sk-ant-...
```

키는 [console.anthropic.com](https://console.anthropic.com)에서 발급받는다.
`.env.local`은 `.gitignore`에 잡혀 있어 커밋되지 않고, 키는 **서버에서만**
읽는다(`src/app/api/generate-skill/route.ts`) — 프론트엔드로 내려가지 않는다.

키가 없어도 **용어 사전(`/glossary`)과 갤러리(`/gallery`)는 그대로 동작한다.**
둘 다 AI를 호출하지 않는 정적 페이지다. 키 없이 `/create`에서 생성을 시도하면
"API 키가 설정되어 있지 않다"는 안내가 뜬다.

### 검사 명령

```bash
pnpm lint            # Biome (lint + format)
npx tsc --noEmit     # 타입 검사
pnpm lint:corpus     # 코퍼스 작성 규칙 (패턴 148개 / 골격 4개)
pnpm check:parser    # 모델 응답 태그 파서 회귀
```

## 참고 코퍼스

생성 프롬프트에는 공개 스킬에서 미리 정리해 둔 "좋은 패턴"이 함께 주입된다.
원문을 런타임에 다시 읽지 않으며, 생성은 구조화된 API 호출 **1회**로 끝난다.

현재 **9개 카테고리 · 패턴 148개 · 문서 골격 4종**, 출처는 **공개 스킬 13개**.
`baseline` 카테고리만 요청 종류와 무관하게 항상 주입된다.

지키는 원칙:

- **소스를 두 등급으로 나눈다.** 라이선스가 확인된 소스(MIT / Apache-2.0)는 값
  리터럴까지 옮기고, 확인되지 않은 소스는 개념·방법만 우리 말로 요약해 담는다
  (문구·목록·표·템플릿은 담지 않는다). **어느 등급이든 출처는 표기한다** —
  표기를 생략하면 화면에서 자체 제작으로 보이는데 그건 틀린 신호다.
- **각 소스의 저장소와 라이선스는 직접 확인해 기록한다.** 검색 결과의 라이선스
  표기는 믿지 않는다. 확인하지 못했으면 `"확인되지 않음"`이라고 적는다 —
  화면에 그대로 표시되는 값이라 추측을 적으면 사용자에게 거짓을 보여주게 된다.
- **표기는 "원문을 읽었다"가 아니라 "정리한 패턴을 참고했다".** 이번 생성에
  실제로 쓰인 것만 표시한다.
- **표기하는 것은 근거를 짚을 수 있어야 한다.** 완성된 SKILL.md에서 확인할 수
  없는 항목은 출처 크레딧에 넣지 않는다.

규칙 본문은 `src/data/reference-corpus.ts` 머리 주석에, 소스 검증 절차는
`.claude/rules/corpus-sources.md`에 있다. 코퍼스가 원문을 제대로 옮겼는지는
`docs/corpus/`에 소스별 감사 기록으로 남긴다 — 파일 목록·바이트·md5까지 적는다.

> 이 판단은 법률 자문이 아니다.

## 구조

```
src/app/                    페이지 + API 라우트
  api/generate-skill/       생성 API (route.ts / prompt.ts)
  api/eval-ab/              실험용 평가 하네스 (개발 전용, 배포 환경에서는 404)
  api/corpus-snapshot/      코퍼스 렌더 덤프 (개발 전용, 배포 환경에서는 404)
src/components/create/      마법사 · 결과 화면 · 이관 패널
src/data/
  reference-corpus.ts       참고 코퍼스 — 패턴 + 문서 골격
  gallery.ts                갤러리 데이터
  glossary.ts               용어 사전 데이터
  wizard-questions.ts       마법사 질문 정의
tools/                      코퍼스 lint · 렌더 대조 · 감사 반영률 · 파서 회귀
docs/corpus/                원문 감사 기록
docs/experiments/           생성 품질 실험 기록 + 원자료
```

`docs/experiments/`의 결론을 인용하기 전에 **각 문서 상단의 정정 문구를 먼저
볼 것.** 나중에 뒤집힌 결론이 있고, 원자료는 측정 당시 상태 그대로 두기 위해
본문을 고치지 않고 정정만 덧붙이는 방식으로 관리한다.

Next.js (App Router) · React · TypeScript · Tailwind CSS · pnpm · Biome
· GSAP + Framer Motion · Anthropic SDK (Claude Sonnet 5)

## 출처

참고 코퍼스는 다른 사람들이 만든 공개 스킬에서 패턴을 정리한 것이다. 각
소스의 저작자와 라이선스는 `src/data/reference-corpus.ts`에, 감사 기록은
`docs/corpus/`에 있고, 생성 결과 화면에도 이번 생성에 실제로 쓰인 패턴의
출처가 표시된다.
